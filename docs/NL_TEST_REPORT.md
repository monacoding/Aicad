# 자연어 입력 100+종 테스트 — 결과 & 개선 보고서

자연어 입력 110개를 AiCAD에 넣어보며 파이프라인(해석 → 검증 → applier → 렌더)을
테스트하고 버그를 잡았습니다. 재현:

```
npx tsx scripts/nltest.mts          # 오프라인 로컬 해석기
npx tsx scripts/nltest.mts --live   # 실행 중인 서버(:8787)+API 키로 실제 Claude
```

## 0. 테스트하다 발견한 가장 큰 문제 → 새 기능

**API 키가 없으면 자연어 기능이 통째로 막힘.** 이 환경엔 `ANTHROPIC_API_KEY`가 없어
실제 Claude 호출이 불가했고, 그 자체가 결함이었습니다. → **오프라인 로컬 해석기**
(`src/cad/nlLocal.ts`)를 폴백으로 추가:

- 서버(Claude) 우선 시도 → 키 없음/빈 응답/네트워크 오류면 **로컬 규칙 해석기**로 폴백
- 도형(원·사각형·n각형·타원·선·호·점·문자·별·집), 변환(이동·복사·회전·축척·대칭·
  간격·배열·채우기·삭제), 레이어, P&ID 심볼/배관/신호, 복합문("A 그리고 B")을 처리
- 키가 있으면 Claude 경로가 우선(훨씬 유연). 키 없이도 기본 작도는 동작.

## 1. 100+ 입력으로 드러난 버그 → 수정

| 버그 | 영향 | 수정 |
|---|---|---|
| **복합문 분리기가 쉼표로 분리** | `중심 3,2 반지름 4 원` → `3`과 `2`가 쪼개져 **좌표가 조용히 (0,0)으로** 망가짐. 다수 프롬프트가 "처리됨"으로 보이나 위치가 틀림 | 연결어(그리고/그다음/;/→/and)에서만 분리, **쉼표로는 절대 분리하지 않음** |
| 치수 프롬프트 미처리 | `치수 0,0 에서 10,0`이 쉼표 분리로 좌표 소실 → add_dimension 0건 | 위 수정으로 정상 (add_dimension 동작) |
| 한국어 수사 n각형 미지원 | `정십각형` 미처리 | NGON 맵에 구/십/십이각형 추가 |
| 광범위 요청 미처리 | `P&ID 전체 시스템`, `공정도` 등 막힘 | 캔드 미니 P&ID 데모 생성(탱크→스트레이너→펌프→체크/게이트 밸브→탱크 + 계기·신호) |

## 2. 결과

| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 처리율 | 101/110 | **106/110** |
| NaN 좌표 | 0 | **0** |
| 좌표 정확도 | 쉼표로 다수 손상 | 정상 |
| 처리 시간 | — | 110개 ~0.4 s |

연산 커버리지(수정 후): add_line/polyline/rectangle/circle/arc/ellipse/point/text/
dimension, add_symbol(43), add_pipe/add_signal, move/copy/rotate/scale/mirror/offset/
array_rect/array_polar/hatch/set_layer — **거의 전 연산을 자연어로 도달**.

남은 미처리 4건은 `멋지게 그려줘`, `아무거나`, `복잡한 도면`, `치수 추가`(좌표 없음)
처럼 본질적으로 모호하거나 창의적 해석이 필요한 입력 — 이는 **로컬 규칙기의 한계이며
실제 Claude 모델이 강한 영역**입니다(키 설정 후 `--live`로 처리).

## 3. 검증/산출물

- 110개 프롬프트(도형·치수·변환·레이어·P&ID·복합·모호한 엣지케이스) 코퍼스
- 대표 9종 렌더(`scripts/out/nl_*.png`): 원, 정육각형, 별, 집, 펌프, 제어밸브, 밸브태그,
  다중 꺾임 배관, "P&ID 전체 시스템" 자동 생성 등
- `tsc` + `vite build` 통과
